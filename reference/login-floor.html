Login floor

Compressed essence of Lesson 02. Print it. Use the glossary words in later lessons. Reach for this before adding MFA, OAuth, or a refresh-token design.

Glossary

TermUse it this way
FloorA control required at the lowest assurance level, whose requirement has survived across revisions. A TODO is not a pass.
VerifierThe code that checks the authenticator. In RunMax, POST /login in route.ts.
EnumerationLearning whether an account exists from any measurable difference: body, status, or time.
ThrottleA cap on failed attempts, answered with 429. Not a hard lock, which lets an attacker disable the account.
Session secretWhat login issues. It must expire, and logout must be able to kill it.
Not the floorNewer, or higher-assurance. Implement only after the floor passes.

The filter

  1. Has the requirement survived, not just the latest number?
  2. Is it a NIST SHALL or an OWASP ASVS Level 1 control, not a SHOULD or Level 3?
  3. Does this verifier actually do it?

Three yeses: floor pass. The requirement qualifies, and the code does not do it: floor fail. The requirement is new or higher-level: not the floor.

Smallest set that clears the floor

  1. Stop logging the password, hash, token, and key. Log login_failed / login_ok with account id, if known, and client IP.
  2. One 401 body for every failure. Dummy argon2.verify when the user does not exist.
  3. Throttle per account and per IP. 429 when the window is exhausted.
  4. Parse with AuthLoginSchema. Cap password length before Argon2.
  5. Refuse to sign unless JWT_SECRET is present and long. Delete the default.
  6. Make verifyToken real, and store something logout can delete.
  7. Serve login only behind TLS.

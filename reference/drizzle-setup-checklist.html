Drizzle + PostgreSQL setup checklist

The compressed essence of Lesson 01. Print it, keep it next to the keyboard, and reach for the error table before you reach for me.

Config invariants

  • drizzle.config.ts schema points at a file that exists — for RunMax: ./src/lib/db/schema.ts
  • schema names exactly one barrel file; it re-exports every table. Second entry points = drift
  • out is committed: drizzle/ with generated *.sql + meta/
  • apps/api/.env exists (both tsx --env-file and dotenv/config resolve it against apps/api/)
  • Container credentials (POSTGRES_USER, POSTGRES_PASSWORD, POSTGRES_DB) are separate from app credentials (DATABASE_URL)

Schema invariants

  • Foreign key column type equals the referenced column type, exactly (uuid → uuid, char(26) → char(26))
  • Every SQL function used in a default exists on your PostgreSQL major version
  • Identifiers: one convention per table (snake_case in SQL, camelCase in TS)
  • updatedAt $onUpdate is Drizzle-side — it fires in ORM updates, not raw SQL

Workflow

CommandDoesWhen
pnpm db:generateDiff schema → new drizzle/NNNN_*.sql (no DB touched)Every schema change; commit the output
pnpm db:migrateApplies pending SQL, records in __drizzle_migrationsDev, CI, deploy
pnpm db:pushDiff schema → DB directly, no SQL fileThrowaway prototyping only
pnpm db:studioBrowser UI over your dataVerification after migrate
Never mix push and generate+migrate on one database. push applies changes the migration table never records, and the next migrate replays them.
